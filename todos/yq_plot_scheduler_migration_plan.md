# yq 剧情调度迁移计划

> 状态：**计划已确认；Phase 0 `deadlineTime` 前置能力已实施，导出包构建与导入尚未实施。**
>
> 本文记录将现有 `yq` 故事导出包接入 RPG World「剧情调度」的实施方案、前置依赖和验收口径。除已完成的 `deadlineTime` 前置能力外，导出包构建器、通用导入器和 `data/48_universe/` 本次均不作修改。

## 1. 目标与固定决策

### 1.1 目标

将现有 yq 故事的四条路线编译为当前 Plot Scheduler 可以消费的 Story 级配置，并以受控本地导入命令写入新工作区：

- `workspace_id`: `48_universe`
- 工作区显示名：`48宇宙`
- 运行根目录：`data/48_universe`
- Story：颜沁单人线、段艺璇单人线、苏杉杉单人线、三人并行线

导入不仅包含角色、世界书、Story、开场、状态表、Composer 与 RP Module 配置，也包含可供后续剧情调度、图片生成和立绘设计使用的事件与视觉规格归档。视觉规格只作为导入报告中的资料索引，不自动创建图片、Media Job 或消息内容。

### 1.2 已确认的行为边界

- 只适配现有「大纲 + 事件池」调度模型；不在此次迁移中实现分支图、条件 DSL、章节 `resolved` / `bypassed` 生命周期或节奏预算。
- 所有导入事件都使用 `soft` 调度，且不可重复。
- 当前大纲节点是**近似软节点**：被注入到某轮 Context 即写为 `triggered`，不代表玩家实际完成了章节。这一限制必须同时写入导入报告和本文件。
- `suitabilityHint` 必须为所有 128 个事件自动生成且非空；它只补充软判断器的信息，不替代通用 Scene、状态、历史和本轮输入判断。
- `reference_route` 只作为归档资料，不作为新 Story 的已发生历史，也不挂载到新 Story。
- 不创建 Session；导入后的角色绑定和 Opening 继续走现有 `/role_bind` 链路。
- 导入命令默认 `--dry-run`，只有显式 `--apply` 才允许写入。
- 工作区或任一目标 Story 已存在时，导入必须在任何写入前停止，并产生零写入的冲突报告；不得尝试合并、覆盖或补写。

### 1.3 本次计划不包含的能力

以下能力在剧情调度基础能力完整后再设计，不应由导入器绕过或伪造：

1. 章节真实完成、跳过和分支收敛的生命周期；
2. 地点、在场人物、状态字段、同意与前置事件的确定性条件门禁；
3. 每池节奏预算、最大并发压力、冷却与活动强度控制；
4. 事件触发、延期、过期的运营预览；
5. 显式分支剧情图。

## 2. 当前实现核对与前置依赖

### 2.1 已可复用的调度能力

当前模型已支持：

- 事件池、事件、大纲和按时间排序的大纲节点；
- `soft` / `forced` 调度模式；
- `suitability_hint`，并会与 Scene、状态表、最近完整 IC/GM 历史和本轮输入一起交给软判断器；
- 每个 IC/GM turn 最多一条大纲候选和一条池事件候选；
- 事件触发后记录到 Session 决策账本；
- 禁用池仍可承载被大纲节点引用的事件。

因此每条路线可采用一个禁用的章节素材池承载大纲事件，另设一个启用的随机可选事件池承载环境事件；两条 lane 的来源不会混淆。

### 2.2 已完成的 `deadlineTime` 依赖

本迁移依赖 `StoryPlotEvent.deadlineTime`；`StoryPlotOutlineNode` 不新增独立字段。可选事件的窗口语义为：候选仅在 `[scheduledTime, deadlineTime)` 内有效，过期事件不得新增决策账本。

该能力是独立前置任务，不包含在 yq 导入器实施中。其完成标准应至少包括：

- 在事件数据模型、SQLite migration、Repository / `PlotSchedulingDataService`、管理应用服务和 API/WebUI 契约中完整传递可选 `deadlineTime`；
- 使用 `SceneTime` 严格解析、序列化和比较，拒绝 `deadlineTime <= scheduledTime`；
- 大纲节点保持无独立 deadline；引用事件的 `deadlineTime` 同时约束事件池与大纲 lane。yq 章节事件继续不设置 deadline，因此主线章节不会因期限失效；
- 候选选择先按有效窗口过滤，再进入 forced/soft 候选判断：事件池使用事件自身的 `[scheduledTime, deadlineTime)`，大纲使用节点 `scheduledTime` 作为起点和引用事件 `deadlineTime` 作为上界；过期项目不写新的 `deferred`、`error` 或 `triggered` 账本；
- 覆盖边界时间、无 deadline、跨月比较、Session override、恢复/重试和账本不写入的测试。

在这个前置任务完成前，导出包可以编译、校验和 dry-run，但 `--apply` 必须明确拒绝写入含 `deadlineTime` 的包，不能悄悄丢弃截止窗口。这样可避免导入出「晚期事件永久可触发」的错误故事语义。

## 3. 目标数据模型与数量

### 3.1 每条路线的 Plot 投影

每个 Story 生成：

| 对象 | 数量 | 配置 |
| --- | ---: | --- |
| 章节素材池 | 1 | 禁用；容纳 14 个章节事件；只由大纲引用 |
| 可选事件池 | 1 | 启用、随机；容纳 18 个一次性软事件 |
| 主线大纲 | 1 | 14 个顺序软节点，逐一引用章节素材池的事件 |
| 章节事件 | 14 | 无 deadline；不参与池 lane；不可重复 |

### 3.3 可选事件窗口

将来源事件的阶段标签编译为以下窗口：

| 阶段 | `scheduledTime` | `deadlineTime` |
| --- | --- | --- |
| `early` | 节点 1 | 节点 5 |
| `middle` | 节点 5 | 节点 10 |
| `late` | 节点 10 | 无上限 |

多阶段事件的开始时间取最早阶段，截止时间取最后阶段之后的下一阶段起点；最后阶段为 `late` 时没有截止。窗口是左闭右开区间：`[scheduledTime, deadlineTime)`。

### 3.4 事件文本编译规则

章节事件的 `directive` 由 `purpose`、`beats`、`playerChoices` 和 `stateEffects` 生成；可选事件由 `premise`、`meaningfulChoices` 和 `stateEffects` 生成。两类 directive 都必须明确：

- 只把事件作为可响应的情境或机会，不替玩家决定行动、对白、感受或承诺；
- 不把尚未发生的后果写成既定事实；
- 拒绝、暂停、非恋爱关系和离开均是完整的合法结果；
- 与职业利益、同意、公开/私密边界相关的限制不可被剧情便利覆盖。

每个 `suitabilityHint` 独立汇总该事件来源中的阶段、地点、在场角色、进入条件、触发说明与安全边界。章节和可选事件分别生成，禁止以同一个路线级字符串复用，避免条件串台。

## 6. 受控本地导入器

### 6.1 边界与组成

建立受版本控制的通用 Story Pack 导入器，并为 yq 包提供受控入口。实现时应只经公开服务写入：

- 增加最小 `WorkspaceManagementDataService`，仅负责工作区的查询和创建等数据事实；
- 通过既有 Catalog、Character、Lorebook、Status、Composer、RP Module、Plot Scheduling 等公开 Data Service / `rpg_core` 应用服务完成业务写入；
- 禁止导入脚本直接使用 Repository、Peewee record 或 SQLite；
- composition root 可以从 `DataServiceGateway` 获取具体服务，但导入业务对象只接收窄依赖，不能持有 Gateway 作为 service locator。

建议命令形态：

```text
rpg-world-import-story-pack \
  --package <yq_story_pack-1.1.0> \
  --workspace-id 48_universe \
  --dry-run

rpg-world-import-story-pack \
  --package <yq_story_pack-1.1.0> \
  --workspace-id 48_universe \
  --apply
```

命令应固定验证目标 ID、显示名和 workspace-relative 运行根路径，避免把这个包误导入其它工作区。对不同 Story Pack 的通用化只能发生在明确的包契约层，不应稀释 yq 的安全规则、适配标签和迁移报告。

### 6.2 预检、写入与报告

导入流程分为不可写入的预检与一次受控 apply：

1. 读取和校验包；编译成内存中的 typed import plan；
2. 查询工作区和四个目标 Story 是否已存在；任一冲突即结束，报告冲突对象，保证零写入；
3. 检查 `deadlineTime` 前置能力。能力缺失时 dry-run 可输出完整计划与阻断原因，`--apply` 必须停止且零写入；
4. 通过预检后，在清晰的事务/补偿边界内依次创建工作区、角色、世界书、Story、挂载、状态模板、Composer、RP Module、Plot 配置；
5. 仅在全部持久化成功后写出完成报告；失败时报告已回滚或待人工清理的边界，绝不伪报成功。

每次 dry-run、冲突和 apply 都写入：

`data/48_universe/imports/`

报告包含：包版本和哈希、命令模式、预检状态、对象计数、源 ID → 数据库 ID 映射（apply 成功时）、未挂载资料、视觉资料索引、冲突、deadline 能力状态、近似软节点限制、异常/回滚结果。报告是运行资料，不提交版本控制。

### 6.3 资料挂载规则

- 11 张角色卡和 59 条世界书按包内关系写入；只有 Story 明确引用的角色/世界书挂载到该 Story；
- `reference_route`、未挂载的资料和视觉规格仅进入导入报告，保留来源可追溯性；
- Composer、Story RP Module 配置和状态模板以包内显式配置为准；不让导入器在运行时做默认选择；
- 不创建 Session、消息、Narrative Outcome、Plot 决策账本、Media Job、TTS Job 或图像二进制。

## 7. 实施顺序

### Phase 0：`deadlineTime` 前置能力（独立任务）

- 完成第 2.2 节的数据、运行时和 API/WebUI 支持及测试。
- 在此完成前，不开始真实 `--apply` 导入；可先完成包构建和 dry-run 编译器。

### Phase 1：导出包编译与校验

- 将本地 yq 构建器升级为 1.1.0；生成路线级调度 projection。
- 修复 Scene、路线进度、状态挂载和视觉资料报告。
- 执行包校验器，确认所有源内容和调度映射完整。

### Phase 2：受控导入器与数据服务入口

- 实现最小工作区管理 Data Service 并登记到 `DataServiceGateway`。
- 实现 pack parser、typed compiler、冲突预检、dry-run 报告和 apply 编排；所有写入经公开服务/API application service。
- 让 importer 识别 deadline 前置能力并在缺失时 fail closed。

### Phase 3：临时数据库验收与真实导入准备

- 使用临时数据库执行 dry-run、冲突路径和完整 apply；不调用真实 LLM、Media 或 TTS。
- 只有所有验收通过，才允许在用户确认后对默认运行数据库执行一次 `--apply`。
- 真实导入完成后，由用户通过 Play WebUI / `/role_bind` 创建首个 Session；不由脚本代建。

## 9. 迁移后待办与风险记录

### 9.1 近似软节点限制

主线事件一旦被注入便记为 triggered，因此玩家可以拒绝、绕开或中断事件，而后续节点仍可能进入候选。yq 的第一版以此换取现有模型兼容性，不能把触发记录用于章节完成度、结局解锁或关系事实推导。

在引入章节完成生命周期前，Story Prompt、directive、导入报告和运营说明均需使用「提出/注入机会」而非「完成章节」的措辞。

### 9.2 后续增强优先级

1. 章节 `proposed → active → resolved / bypassed / expired` 生命周期与人工/LLM 可解释确认；
2. 明确的地点、在场人物、状态、已发生事件和同意条件门禁；
3. 池级节奏预算、冷却、连发保护和张力管理；
4. 调度预览（将触发、延期、过期原因）与可审计模拟；
5. 在上述模型稳定后，再引入显式分支图和汇合节点。

### 9.3 风险与缓解

| 风险 | 缓解方式 |
| --- | --- |
| deadline 能力未落地就导入 | importer fail closed；不丢弃 deadline，`--apply` 零写入停止 |
| 章节被误解为已完成 | 统一标记为近似软节点，并在报告和 UI 文案中明确 |
| 状态模板误共享或角色归属丢失 | Story-owned 模板与角色 mount 测试；禁止「未知角色」降级 |
| 导入重复/部分写入 | 全量预检、冲突即零写入、受控事务/补偿边界和持久报告 |
| 真实人物与视觉资料被误作现实事实 | 保持 `fictional_adaptation`、reference-only、非新闻证据和不自动生图边界 |

## 10. 完成定义

本迁移仅在以下条件全部满足时视为完成：

- `deadlineTime` 前置能力已上线并通过其独立验收；
- `yq_story_pack-1.1.0` 校验通过，四条路线的调度 projection、状态模板和视觉归档完整；
- 受控导入器在临时数据库通过所有第 8 节自动验证；
- 对目标运行环境的 `--apply` 经用户确认后成功，报告写入 `data/48_universe/imports/`；
- 未创建未授权 Session、真实媒体任务或错误的剧情决策账本；
- 本文第 9 节的限制和后续任务已保留，未被导入器或产品文案掩盖。
